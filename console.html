How often is "at risk" recalculated?

Scores are recomputed weekly, by the model training job. That's deliberate rather than a limitation:

The signal moves slowly. What's being predicted is how likely someone is to come back, which changes on the timescale of visit intervals - weeks, not hours. Rescoring daily would churn the tiers without adding real information, and costs a full training run each time.

Your win-back campaigns don't depend on it. Nudge and lapsed are recalculated from real transaction dates on every agent run, so they're already daily-fresh. These scores drive this card and the insights, not the day-to-day outreach - so weekly scoring doesn't mean week-old messaging.

Staleness is already handled. If someone returns mid-week they'll still show here until the next run, but outreach skips anyone with a message already in flight, and their visit resets campaign eligibility anyway. Monthly would also be defensible; daily mainly adds cost.

First time with a brand-new number? Register it here

A genuinely new WhatsApp number shows "Pending" in Meta until it's registered for Cloud API use - this is a separate, one-time step from just connecting it below. Uses the access token and phone number ID entered below, so fill those in first.

Language code must match exactly what the template shows in Meta's dashboard - "en" and "en_US" are genuinely different and won't match each other, even though they look similar. Header and body have their own, separate {{1}}, {{2}} numbering in WhatsApp's template structure - they're not the same slots, even when both use {{1}}. hello_world only exists for accounts that went through Meta's free test-number flow - if this account connected a real number directly instead, use one of your own real template names here.

curl -X POST https://wtapyfgtwkjyjrjdnhkb.supabase.co/functions/v1/mw-ingest \ -H "x-tenant-key: YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{"action":"upload_transactions","rows":[{"mobile":"971501234567","date":"2026-08-11","amount":150,"external_id":"INV-1042"}]}'

Including external_id (your own invoice/order number) is optional but recommended if you also upload Excel exports of the same data - it prevents the same sale from being counted twice.
